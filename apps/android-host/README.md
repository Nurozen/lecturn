# Lecturn Android host

Standalone Java Android shell for the phone-local fullweb UI. It does not contain, start at boot, or simulate the Lecturn server. The launcher package is `com.cloudgatherer.lecturn.symba`, label **Lecturn**. The native book vector is derived directly from `../../assets/lecturn/mark.svg`; the adaptive launcher icon uses that unchanged mark over an edge-to-edge navy background.

Build with JDK 21 and Android SDK 36:

```sh
JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home \
ANDROID_HOME=/Users/nurozen/Library/Android/sdk \
./gradlew --no-daemon :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Tests and lint reports are under `app/build/reports/`. This is a debug APK for parent-controlled installation and device verification.

Open **More → Set up agents** to sign in to Codex or Claude locally. The phone build uses Codex device login and Claude’s manual browser/code flow; the sign-in terminal must stay open until completion. Provider credentials stay in the Linux guest.

For screen-off agent work, open **More → Background battery**. The row reads Android's current battery-optimization exemption each time the menu opens. **Optimized** means no package-level Doze exemption is enabled; background work may be interrupted. A running foreground-service UID can already receive [Doze protection on Android 16](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android16-release/services/core/java/com/android/server/power/PowerManagerService.java), so this status alone does not establish whether the host or guest traffic is blocked. **Continue to Android** opens the system exemption request; accepting is optional and may increase battery use. Declining keeps foreground use available. **Exempt** permits network and partial wake locks during Doze, but is not a guarantee of uninterrupted execution. Reopen More after returning from Settings to check the actual state. The same entry opens battery settings when exempt so you can revoke it. No request appears automatically during launch or provider login, and this choice does not start, stop, or restart the runtime or change device-access approvals. See Android's [Doze restrictions and exemptions](https://developer.android.com/training/monitoring-device-state/doze-standby).

## Bootstrap and authority boundary

The parent runtime integration must provision `files/host-config.json` in this app's private internal directory, owned by its app UID with mode 0600. The object contains `controlToken` (a generated 64-hex string) and `controlPort` (the number 18768). There is deliberately no token input field, asset, external-storage bootstrap, grant intent, or credential copied from a development machine. Backup and device transfer are disabled. This shell never logs config, control responses, authenticated URLs, WebView console messages, or transport exceptions.

The control server must bind to `127.0.0.1:18768` and authenticate every endpoint using that bearer token. The app implements the supplied schema-version-1 contract: `GET /v1/state`, `POST /v1/runtime/start {}`, `POST /v1/runtime/stop {}`, and `POST /v1/policy {expectedRevision,fullAccess,computerUse}`. Successful responses must be HTTP 200 with a complete state **after** the operation completes. HTTP 409 triggers a fresh state fetch and a new user review, never an automatic grant retry. Redirects, malformed state, unknown enums, coerced types, and non-loopback UI/task URLs fail closed. The controller serializes requests, queues Stop behind an in-flight request, and bounds network waits (3-second connect / 12-second read). A slow operation can complete server-side after a client timeout; subsequent status polls recover observed state without claiming success early.

`capabilities.appData` gates Full access; `capabilities.computerUse` independently gates Computer use. The parent must only advertise capabilities its runtime really implements and must enforce revision checks and grants at the actual execution boundary. The shell does not grant Android sandbox exemptions, hardware keys, other profiles, accessibility, or all-files access. The current effective device policy is app-wide across all Lecturn tasks. Fullweb provider approval modes remain per thread. Selecting Full or sending with a persisted Full default requires verified native access; other provider modes do not revoke the app-wide grant. Computer use is a separate selection, requires Full access, and is enabled only when the broker advertises support. The native confirmation explains that app data remains available in the background and while locked after the first unlock following a restart; computer use requires a visible, unlocked screen. The broker owns enforcement of both policies.

## Web and lifecycle contracts

Only `http://127.0.0.1:3773` is trusted in the WebView. `uiUrl` and `taskUrl` must use this literal origin, with an explicit port. Pairing links stay in process/private WebView storage. HTTPS links and OAuth popups open in the external browser without forwarding native credentials. Other origins/schemes are rejected. Cross-origin embedded resources are blocked. No `desktopBridge` is created.

The origin-scoped, main-frame-only `window.symbaHost` uses `protocolVersion: 2`. `getAccessState()`, `requestFullAccess(threadId)`, and `openDeviceAccess()` return promises correlated by request ID. The reply exposes only `{verified, revision, fullAccess, computerUse, capabilities: {appData, computerUse}}`. Full access succeeds only after a fresh broker read confirms an existing grant, or the user confirms native review and the broker returns a newer applied revision with the requested grants. Cancellation, conflict, Stop, disconnect, stale review, and departed documents cannot authorize a send. There is no arbitrary URL, command, token, or policy mutation method. Reads never grant access; page events never apply policy.

Pending requests are limited to 16 and only one native review can be open. Native requests expire after 85 seconds; the injected page promises expire after 90 seconds. Navigation, pause, renderer failure, and destruction drain pending requests as unverified. Returning to the app refreshes the visible native status, and every Full send reads current policy again. WebViews without scoped-message/document-start support must be updated before loading fullweb; there is no fallback Java object bridge.

Run the injected protocol tests with `node --test tests/access-bridge.test.mjs`. The APK supplies the native bridge, but **the fullweb bundle must also be rebuilt** for its Full-mode guard; an older published server UI does not include it.

`uiUrl` is the stable, credential-free `http://127.0.0.1:3773` (optional trailing slash); state URLs cannot carry query strings or fragments. Native code checks `GET /api/auth/session` with only the WebView cookie, requiring a JSON boolean `authenticated`. A transport error does not count as unauthenticated. If false, it calls authenticated control `POST /v1/ui/bootstrap {}` once. That response is separate from state: `{schemaVersion:1,pairingUrl,expiresAt}`, with the exact URL `http://127.0.0.1:3773/pair#token=<12-character one-time credential>` and a future ISO instant. Only this one-time URL reaches the WebView; the native control token never does. Bootstrap does not apply device policy or refresh working-state freshness.

The host checks the cookie session before opening the latest fresh `taskUrl`. It waits at most 30 seconds (or the credential expiry, if sooner) for pairing and never remints on state polls. Failure, consumption or expiry requires **More → Retry pairing**, which checks the session first and mints a new link only if still unauthenticated. Reload uses the credential-free root, never the old pair URL. Navigation, pause and Stop discard late callbacks; the attempt latch survives activity recreation. Fullweb OAuth, pairing, uploads, and routes must be verified against the parent's actual Linux runtime.

Start is a native user gesture and requires visible notifications. It starts the foreground `specialUse` service and sends the real POST start. If the runtime is already verified ready or starting but the service is absent, **Keep running** attaches monitoring without restarting the runtime. There is no boot receiver or process-death auto-start. The service survives activity destruction, polls every 3 seconds while working, 8 seconds otherwise, or 10 seconds after failures, and marks unrefreshed state stale after 20 seconds. A fresh controller `starting` receipt is represented as runtime `starting` with idle activity and no UI URL; only controller readiness plus authenticated API health becomes `ready`. A separate startup wake lock renews only on new, fresh authenticated `starting` receipts, with each lease ending by the 20-second freshness deadline and a five-minute continuous-startup cap. Stop, unverified status, runtime exit, or stale/error activity releases it. Lost contact does not reset the cap; only fresh confirmed `ready` or `stopped` state does. The budget survives service recreation within the controller process. Working wake lock leases last at most 30 seconds and renew near halfway through the lease only on a new, fresh authenticated working-state receipt. This supports long tasks with the screen off when Android honors the leases. The optional battery exemption above adds package-level Doze protection; actual host and guest execution still needs device qualification. Stop, failed/stale runtime status, or no active work releases immediately. Device grant changes and temporary computer-use unavailability do not stop Linux work or release its lease. Limited tasks can hold leases without receiving device grants. Long-running runtime execution remains the parent's responsibility; the shell is not a daemon supervisor.

The native header uses the official Lecturn book, navy and warm gold, with Device access and More controls. The initial waiting surface shows observed runtime state without work animation; the full web workspace takes the remaining screen once available. Stop is available through More, the waiting surface while running, the notification, and the expanded overlay. The service exits after a verified stopped response to Stop. A failed stop stays visible and retryable; it never claims the server stopped. Overlay permission is optional and user-granted in Android Settings. The 56dp book flips a page at about 6 FPS whenever fresh `ready` state reports any working task, while the selected waiting/error thread remains visible for attention. Without active work, the book is static. Schema-version-1 activity adds `hasWorkingTasks` (boolean) and `workingCount` (nonnegative integer), aggregated across nonarchived working threads independently of the selected thread. The host requires both fields to agree; older brokers omitting both retain selected-thread behavior. Screen-off/keyguard hide the overlay, reduced motion disables animation, drag positions clamp to display bounds, and Minimize collapses without stopping. No hidden animation runs.

File uploads use the system document picker. Local HTTP downloads copy through the app to a user-chosen document (256 MiB / 2-minute limits); redirects are rejected and URL/cookies never enter DownloadManager. Fullweb blob exports are captured before URL revocation and copied in 32 KiB chunks (16 MiB / 2-minute limit), only after a save-picker result. Export names are generic so authenticated URLs never become filenames. External HTTPS downloads open in the browser. System document pickers do not grant the agents device-wide file access.

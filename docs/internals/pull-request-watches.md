# Pull request watches

`PullRequestWatchService` owns durable watches, defaults, and command receipts in migration 052 tables. These tables survive projection resets. Watch identity includes project, canonical host/repository and PR number; its authority additionally binds workspace root, Stave incarnation, physical checkout and repository canonical identity.

`PullRequestWatchProvider` expands editable manifests, refuses reference aliases, rereads Stave incarnation and repository membership, and shares provider rate limiting with the existing PR service. Detail and acceptance evidence remain separate: unknown required checks never count as green. The PR service revalidates the resolved action binding and account permissions before dispatch.

A scoped, activation-parked worker reconciles durable watches without requiring an open client or running manager. A separate bounded discovery worker scans active/recent threads using verified non-default branches and viewer-authored PRs; explicit thread links also add associations. Neither path assigns a manager. Saga managers may cover descendant spaces using the same verified root-and-incarnation roster as the hierarchy. A standalone checkout alias only covers its matching repository within a space; unrelated repositories, projects and reference aliases are refused.

Legacy merge authorization remains an intent owned by the server, not a provider auto-merge setting. Current watch controls no longer create it; they retain revocation for existing authorizations. Both modes wait for fresh required-check evidence for the observed head, mergeability and provider permissions. Follow-PR mode updates the merge candidate across commits; revision-only invalidates on a changed head. Both invalidate on a changed base branch or repository binding. Existing native auto-merge must be disabled and confirmed before the watcher takes control. Watched GitHub merges use the synchronous REST merge endpoint with the expected `sha` and require a `merged: true` response; this cannot silently enroll the PR in a merge queue or enable native auto-merge. Providers without an equivalent capability remain blocked. GitHub has no atomic base-branch precondition: the base is checked immediately before dispatch, but a concurrent remote retarget inside the final host request cannot be fenced by the current host API.

Commands carry actor-scoped request IDs and persisted receipts. Merge confirmation includes the shown head, base and binding. Intent is stored before external effects; reconciliation reads provider state after an uncertain response. Pause/revoke is retried until provider automation is confirmed disabled. A missing or changed binding cannot be reported as successful revocation of inaccessible old provider state. Resume/retrack can recover the same canonical PR only after fresh facts prove native automation disabled (or the PR terminal); it clears prior authorization and management before rebinding.

`repositoryScope` in client-runtime resolves thread, space, saga and selected project-group roots, deduplicating by environment plus physical checkout. PR views supply the verified saga roster and submit the resulting project union, so duplicate or reused saga names cannot replace workspace identity. The shared watch runtime exposes query/command atoms; UI observation is separate from the server's durable poller.

The desktop activity window has an isolated sandboxed preload, no credentials and no network access. Only the authenticated main renderer publishes rows. Main-frame sender checks, complete row identity and watch revision checks reject stale or forged actions. The main renderer executes RPCs and quick steer. Enable-state changes are pushed from the menu bar to avoid permanent renderer polling. Electron exposes no camera safe-area API; internal-display menu-bar geometry provides a conservative camera-strip reservation. The frameless window starts at the display edge with Electron’s larger-than-screen constraint override, leaving the central camera housing empty, putting compact controls in its side wings and extending the expanded body below it; ambiguous displays use the menu-bar fallback.

PR watches publish independent relay activity identities (`pr-watch:<watchId>`), rather than borrowing a manager's activity lifetime. PR facts include CI, required checks, watch state, manager state, authorization and freshness. The signed Connect path and billing checks are unchanged. Activity aggregate content is bounded to 3,200 UTF-8 bytes and at most five rows to leave room inside APNs/ActivityKit envelopes. Counts retain the total when fewer rows fit. Live PR heartbeats run every five minutes, below the ten-minute APNs stale deadline. Terminal PR updates do not receive periodic heartbeats: completedAt is persisted only on an observed open-to-terminal transition, and terminal cards expire after fifteen minutes. Initially discovered historical completions are not notified.

Mobile activity links open authenticated PR controls. They never execute a merge from URL parameters. Quick steer uses the app's durable outbox; widgets cannot host a free-text composer. Apple controls system rendering and mirroring availability. No native device receipt or delivery success is inferred from a locally emitted Expo button event.

Web and native quick-steer retries persist the original command identity across ambiguous transport failures. An edited draft is refused before any old command is resent; the user must retry the original text to confirm its outcome before sending different instructions.

Repository grouping may deliberately identify an upstream repository. PR listing instead resolves the editable checkout’s actual remotes and defaults to `origin` (or the first available remote). Discovery checks all verified remotes and binds the resulting watch to its physical checkout. Explicit upstream references remain addressable. New prompt/turn evidence triggers discovery without waiting for its idle cooldown. Association discovery never resumes a paused watch or assumes management ownership.

Active desktop/web watch lists exclude paused watches; resumable history is separate and its manager transcripts are loaded only when expanded. The relay publishes a tombstone for a paused open watch on its next bounded publication cycle (at most 30 seconds before delivery latency). Activity text uses current plan progress, the current turn’s latest assistant response, explicit approval/input/error state and observed timestamps. It does not infer that an agent is stuck from elapsed time. Native context subscriptions are capped at twelve threads and IPC publications coalesced to 300 ms. Animated gold perimeters run only for visible foreground working cards and honor reduced motion.

Current web, mobile, and native watch controls send `mergeHandoffMessage` through the durable thread message path. `selectMergeHandoffThread` uses the eligible explicit manager, or the sole eligible associated thread when no manager is assigned. An unavailable explicit manager never silently falls back. Multiple associations require selection. Active legacy server authorizations block handoff until revoked. Choosing handoff to a sole associated thread first persists that thread as manager; a failed assignment prevents the send. A send receipt acknowledges the instruction, not agent completion or a merge. Pausing a watch cannot cancel a previously delivered agent message.

The Mac activity bridge persists bounded local route interactions and combines them with latest user-prompt timestamps to retain three recent threads. Background status updates do not reorder that history. Other active threads remain visible. Native PR rows carry up to fifty structured CI jobs plus their total; disclosures retain their expansion state across updates.

The native panel distinguishes collapsed, hover-peek and explicitly expanded modes. Peek is bounded to three priority-sorted rows and does not take focus. Manual expansion makes the panel focusable and focuses it once; routine placement does not call showInactive repeatedly. Hover exit cannot collapse an explicit expansion. Outside focus loss dismisses expanded content, while interior resize/focus transitions do not.
